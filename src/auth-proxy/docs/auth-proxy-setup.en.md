# auth-proxy: set-up guide, CLI first (short English version)

The Worker once called `models-github-proxy` (it served GitHub Models) now mainly serves **authentication**: it keeps the Google, Microsoft and GitHub App client secrets so the site stays connected to Google Drive, OneDrive and (with a later site release) GitHub. So it is now **`auth-proxy`**, lives in `src/auth-proxy/` and stays on Cloudflare. It still contains the GitHub Models proxy, **being retired**: delete it when GitHub Models are gone. The full Italian guide, with a **Verifica** line per step, is [`guida-auth-proxy.it.md`](guida-auth-proxy.it.md); technical reference: [`../README.md`](../README.md).

"Verified" means I read the command's own help (`--help`, `cf cli search`, `cf schema`) or ran it with `--dry-run` without credentials; what I could not verify is listed in section 8. Sources (read 2026-11-23) in section 9. **Rule zero:** no secret on a command line, in an issue, chat, commit or `wrangler.toml`; every command that needs your secret reads it from hidden input or stdin.

## 0. State

Done in this change: the code moved from `infra/models-github-proxy` to `src/auth-proxy`; `wrangler.toml` says `name = "auth-proxy"` (a NEW Worker at `https://auth-proxy.alessandro-rapiti44.workers.dev`; the old one is untouched and the site keeps using it until `VITE_GITHUB_MODELS_BASE` changes); the workflow is `deploy-auth-proxy.yml` ("Deploy auth proxy": tests, secret upload, `wrangler deploy`, then a Google/Microsoft/GitHub table read from the Worker it just deployed: the URL is the deploy step's `deployment-url` output, the repository variable is only the fallback); the Worker is not an npm workspace and has no Wrangler dependency; scripts `set-secrets.sh`, `check-status.mjs`, `check-microsoft-app.sh`. Repository secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` exist.

## 1. Tools and sign-in

- **`gh`:** `gh auth status` (needs the `repo` and `workflow` scopes; else `gh auth refresh -s workflow`).
- **`cf` (Cloudflare CLI, 1.0 RC):** `npm install --global cf`; `cf --version` (verified 1.0.0-rc.4); `cf auth login` (`--no-browser` prints the link instead of opening it); `cf auth whoami`; `export CLOUDFLARE_ACCOUNT_ID=<id>` (needed non-interactively). **`cf` does not reuse the Wrangler login** (two separate sign-ins); an exported `CLOUDFLARE_API_TOKEN` wins over the login. *Verify:* `cf workers list` shows your Workers.
- **Wrangler:** no longer a repo dependency: `cd src/auth-proxy && npx wrangler login` (`--device` without a browser), `npx wrangler whoami`.
- **`az`:** `az login --allow-no-subscriptions` (`--use-device-code` without a browser); *verify:* `az ad app show --id a80b2024-b9e3-4cb1-8480-aac7f164a6eb --query displayName -o tsv`.
- **`gcloud` (optional):** `gcloud auth login`; `gcloud config set project <id>`.

## 2. Moving the Worker (the site must work at every moment, so the old Worker goes last)

- **2.0 Check the client IDs match** (they are already in the repo; nothing to supply): `grep -ho '91477716497-[a-z0-9]*\.apps\.googleusercontent\.com' src/auth-proxy/wrangler.toml src/narrarium-site/src/config/publicClients.ts` and the same for `a80b2024-[0-9a-f-]*`: two equal lines each.
- **(a) Merge this change into `main`.** The merge itself starts `deploy-auth-proxy.yml` (it deploys the NEW Worker, without secrets: the table says "not configured") and also "Deploy Narrarium Site" (the root `package.json` changed: same site rebuilt). `gh run list --workflow deploy-auth-proxy.yml --limit 3`, `gh run watch <id> --exit-status`. *Verify:* green run, the summary shows the Worker URL; `cf workers list` shows both Workers.
- **(b) Deploy the new Worker** if it did not start: `gh workflow run deploy-auth-proxy.yml`. The new Worker is **created** by the token you already have; do not tighten the token first (creating a Worker needs a higher permission than updating one; see 5.1). *Verify:* `cf workers deployments list --worker auth-proxy`.
- **(c) Set the client secrets (hidden input):** `src/auth-proxy/scripts/set-secrets.sh --dry-run`, then `src/auth-proxy/scripts/set-secrets.sh` (Google `GOCSPX-…`, the Microsoft **Value** not the Secret ID, Enter to skip GitHub; optional deploy at the end). It uses `read -rs` and pipes the value to `gh secret set` on stdin. *Verify:* `gh secret list` (names only); after the deploy `cf workers secrets list --worker auth-proxy` shows `GOOGLE_CLIENT_SECRET` and `MICROSOFT_CLIENT_SECRET`.
- **(d) Check the new Worker:** `node src/auth-proxy/scripts/check-status.mjs https://auth-proxy.alessandro-rapiti44.workers.dev` (URL as argument; the repository variable is only a fallback and still points to the OLD Worker) and `curl -s <new>/oauth/status`. *Verify:* `{"google":true,"microsoft":true,"github":false}`. Credentials test with a made-up token: `curl -s -X POST <new>/oauth/google/refresh -H 'Content-Type: application/json' -d '{"refreshToken":"test"}'` must say `invalid_grant` (`invalid_client` = wrong id or secret).
- **(e) Switch the site:** `gh variable set VITE_GITHUB_MODELS_BASE --body https://auth-proxy.alessandro-rapiti44.workers.dev`, then `gh workflow run book-management-system.yml` and `gh run watch --exit-status`. *Verify:* the browser's Network tab shows `/oauth/status` going to the new host.
- **(f) Test real connections:** reconnect Google Drive (stay signed in beyond 1 hour) and OneDrive (beyond 24 hours). A Google `redirect_uri_mismatch` is the known untested case of 4.3.
- **(g) Only then delete the old Worker**, after a few days (browsers with the old site cached still use it): `cf workers delete models-github-proxy --dry-run` (shows the DELETE request, verified), then `cf workers delete models-github-proxy` (asks for confirmation, `-f` skips it); equivalent: `npx wrangler delete models-github-proxy --dry-run` then without `--dry-run`. *Verify:* `cf workers list` no longer shows it.

## 3. Microsoft with `az`

- **3.1 Look (read-only):** `src/auth-proxy/scripts/check-microsoft-app.sh` prints the sign-in audience, the Web / SPA / public-client redirect URIs (OK / MANCA for each of the four expected callbacks, read from `wrangler.toml`), the delegated Graph permissions and each client secret's **expiry** (never its value). It changes nothing and prints the command to run; exit 0 all fine, 3 something missing.
- **3.2 Audience** (only if flagged): `az ad app update --id a80b2024-b9e3-4cb1-8480-aac7f164a6eb --sign-in-audience AzureADandPersonalMicrosoftAccount` (the Worker uses the `common` authority).
- **3.3 Web redirect URIs, MERGING:** `--web-redirect-uris` **replaces the whole list**, so list the existing ones (`az ad app show --id $APP --query "web.redirectUris" -o tsv`) and pass them together with the four: `https://narrarium.net/auth/microsoft-callback.html`, `https://www.narrarium.net/auth/microsoft-callback.html`, `http://localhost:5173/auth/microsoft-callback.html`, `http://localhost:4173/auth/microsoft-callback.html` (the script prints the merged command). The SPA URIs (`…/msal-popup.html`) are a different property and stay. Never register the four under "Single-page application" (24-hour refresh tokens, `AADSTS9002327`).
- **3.4 Delegated permissions, no admin consent, ids looked up not typed:** `for p in User.Read Files.ReadWrite offline_access openid profile; do id=$(az ad sp show --id 00000003-0000-0000-c000-000000000000 --query "oauth2PermissionScopes[?value=='$p'].id | [0]" -o tsv); az ad app permission add --id $APP --api 00000003-0000-0000-c000-000000000000 --api-permissions "$id=Scope"; done`. Do not run `admin-consent`/`grant`: users consent at first connection.
- **3.4b `AADSTS90023` ("Public clients can't send a client secret"):** Microsoft treats the app as a public client. Either **Allow public client flows** is on (`az ad app update --id $APP --is-fallback-public-client false`; the SPA URIs MSAL uses are untouched), or one of the four `…/auth/microsoft-callback.html` URIs is registered under **Mobile and desktop applications** (remove it there, keep it under Web). `check-microsoft-app.sh` reports both. *Verify:* the script says the public-client flag is off and no URI is `SBAGLIATA`; a new OneDrive connect succeeds.
- **3.5 Secret expiry and rotation:** max 24 months; calendar reminder 30 days before. Rotate without downtime: create a **second** secret (portal, or `az ad app credential reset --id $APP --append --display-name narrarium-worker --years 2 --query password -o tsv | tr -d '\r\n' | gh secret set MICROSOFT_OAUTH_CLIENT_SECRET`; without `--append` it **deletes every existing secret**), `gh workflow run deploy-auth-proxy.yml`, `check-status.mjs`, a test connection, then `az ad app credential delete --id $APP --key-id <id>` for the old one (ids from `az ad app credential list --id $APP --query "[].[keyId,displayName,endDateTime]" -o tsv`).

Add the same four origins under **Authorized redirect URIs** too: it costs nothing and covers the second case.

## 5. Cloudflare hardening (optional, after everything works)

- **5.1 Least-privilege token, after the first deploy of the new Worker.** `cf accounts tokens permission-groups list --name Workers%20Scripts%20Write` (name URL-encoded; **look the id up, never hard-code it**); build `[{"effect":"allow","permission_groups":[{"id":"<id>"}],"resources":{"com.cloudflare.api.account.<ACCOUNT_ID>":"*"}}]` into a file; `cf accounts tokens create --name narrarium-auth-proxy-deploy --expires-on <date> --policies @file --dry-run` (add nothing else; drop `--dry-run` to create). The creating caller needs the right to create tokens: if the `cf` login is not enough, use an admin token read once from hidden input (`read -rs`) and `unset` it. The value is shown once: pipe it to `gh secret set CLOUDFLARE_API_TOKEN`, never leave it on screen. **"Workers Scripts Write" is account-wide** (all Workers); narrower is the **Editor role on a single Worker** (dashboard; I could not verify how to express it in `--policies`). An Editor token cannot create or delete Workers. Then `gh workflow run deploy-auth-proxy.yml`; **only if green** delete the old token (`cf accounts tokens list`, `cf accounts tokens delete <id>`; a personal token via the dashboard). Rotate with `cf accounts tokens roll <id>` (invalidates the old value at once) then `gh secret set` and a deploy. If the deploy fails with error 10000 add *Account Settings → Read*.
- **5.2 Look at the Worker:** `cf workers get auth-proxy`, `cf workers deployments list --worker auth-proxy`, `cf workers versions list --worker auth-proxy`, `cf workers secrets list --worker auth-proxy` (names only); Wrangler: `npx wrangler deployments list --name auth-proxy`, `npx wrangler versions list --name auth-proxy`, `npx wrangler secret list --name auth-proxy`; `cd src/auth-proxy && npx wrangler deploy --dry-run --outdir /tmp/auth-proxy-out` (no login; shows `env.OAUTH_RATE_LIMITER (30 requests/60s) Rate Limit`).
- **5.3 Live logs without touching the Worker's observability setting:** `npx wrangler tail auth-proxy --status error --format pretty` works without Workers Logs. `cf observability tail --worker auth-proxy` **requires Workers Logs** (per its help); they are on for this Worker only if Cloudflare's default for new Workers applies (`wrangler.toml` does not declare them and I could not see the real state: check the dashboard). Do not change the setting just for that. Do not paste the output anywhere.
- **5.4 Rate limiting:** the in-memory limit (30 POSTs/min per address per isolate) and the **already existing** binding `OAUTH_RATE_LIMITER` (30 per 60 s per address per location, approximate, not in the dashboard, Wrangler ≥ 4.36; `namespace_id` `7301` must be unique in the account): do not add another. WAF rate-limiting rules **cannot be applied on `workers.dev`**; they need a custom domain (Free plan: 1 rule, 10 s window, per IP, path filter). Test, no secret needed: 35 `curl -s -o /dev/null -w '%{http_code} ' -X POST <new>/oauth/microsoft/revoke -H 'Content-Type: application/json' -d '{"token":"x"}'` → about 30 `204` then `429`.
- **5.5 Never:** secrets in issues/chat/commits/`wrangler.toml`; account-wide admin or "all accounts/zones" tokens, the Global API Key; **`cf workers secrets update <name> --text <value>`** (the value becomes an argument: use `set-secrets.sh`/`gh secret set`); editing Worker variables in the dashboard (the next deploy overwrites them); enabling `[observability]` without a reason.
- **5.6 `cf deploy` instead of Wrangler? Not now.** In a project with `wrangler.toml`, `cf deploy` does not replace Wrangler, and Cloudflare's docs say **never run `cf dev`, `cf build` or `cf deploy` in an unmigrated Wrangler project**. Deploys stay with Wrangler through the workflow. `cf migrate` is an optional later step (`cd src/auth-proxy && cf migrate --dry-run --force` previews: on a copy it said "Would update 3 file(s): cloudflare.config.ts, package.json, package-lock.json", no manual follow-ups); it adds `cf` as a dependency and would change the workflow, so I do not recommend it yet.
- **5.7 Custom domain `auth.narrarium.net` (optional):** your own URL and WAF rules, at the price of moving the DNS of all of `narrarium.net` from GoDaddy to Cloudflare. **Domains → Onboard a domain** → Free plan; review every imported record (GitHub Pages for `@`/`www`, mail), site records **DNS only** (grey cloud); turn DNSSEC off at GoDaddy first; change the nameservers at GoDaddy; wait for **Active**; add `[[routes]] pattern = "auth.narrarium.net"`, `custom_domain = true` to `wrangler.toml` (keep `workers_dev = true` meanwhile; the token needs Zone → Workers Routes → Edit on that zone); deploy; `gh variable set VITE_GITHUB_MODELS_BASE --body https://auth.narrarium.net` and rebuild; `ALLOWED_ORIGINS_EXTRA` does not change (it lists *site* origins); finally `workers_dev = false`.

## 7. Final checklist and what to enforce

`gh secret list` · `set-secrets.sh --dry-run` · `gh workflow run deploy-auth-proxy.yml && gh run watch --exit-status` · `node src/auth-proxy/scripts/check-status.mjs <new URL>` · `src/auth-proxy/scripts/check-microsoft-app.sh` · `cf workers list`. `{"google":true,"microsoft":true,"github":false}` = Google and Microsoft ready; a `false` = that secret (for GitHub also `GITHUB_APP_CLIENT_ID`) is missing; no `github` key = an old Worker is still live.

| Enforce | Where | Why |
| --- | --- | --- |
| Cloudflare token: only "Workers Scripts Write" (or Editor on one Worker), your account only, expiry + reminder; tightened **after** the first deploy | Cloudflare | a leak can only redeploy that Worker; creating a Worker needs more than updating one |
| Secrets only in GitHub secrets via `set-secrets.sh` (stdin), never as arguments | GitHub / Worker | no history, no process list |
| Old Worker deleted last, after real tests and some days | Cloudflare | cached site builds still call it |
| Google consent screen **In production**; exact origins | Google Auth Platform | 7-day refresh tokens in *Testing* |
| Microsoft URIs under **Web**, **merged** with the old ones; no admin consent; secret ≤ 24 months with reminder and a second secret for rotation | Entra | the secret is accepted; MSAL URIs are not lost; no OneDrive outage |
| GitHub App: token expiry on, wildcard off, webhook off, no Administration/Pages, installed only on the book repositories | GitHub | short-lived tokens, minimal consent |
| No PAT or app token in synced data | site | a plaintext token on Drive or a public repo is lost |
| Do not touch `observability`; variables only from `wrangler.toml` | Worker | no traces, no drift |
| Rate limits: in code + `OAUTH_RATE_LIMITER`; WAF rule only with a custom domain | Worker / Cloudflare | `workers.dev` accepts no WAF rules |
| Workflow permissions `contents: read` only | `deploy-auth-proxy.yml` | the workflow cannot write to the repository |
