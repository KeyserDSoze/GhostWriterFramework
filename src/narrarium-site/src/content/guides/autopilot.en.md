# Autopilot, director and personal server

The autopilot writes the book step by step: concept, chapter plan, scenes, simulated readers, specialists and the director's decisions. In the menu of a book its group has two pages: **Live**, what the autopilot is doing, and **Configuration**, its brief and its settings. **Autopilot** in the library shows every book.

## Start

Open **Configuration**, write an idea (one sentence is enough) or a binding chapter-by-chapter synopsis, choose a size (see *What to expect from a run*) or your own chapters, scenes per chapter and words per scene, then **Start autopilot** at the bottom of the page: the autopilot starts and **Live** opens. A book that never started shows **Configure the autopilot** on its live page. When the book has an **Outline**, the autopilot follows it as binding, and it fills in the chapters the Outline does not have yet (see *The Outline (Scaletta)*). By default it pauses when the plan is ready: read it, then **Approve the plan and continue**. A book that already has chapters is continued after the last one.

## The configuration

**Configuration** has the settings in seven tabs: **Overview**, **Review**, **Retries**, **Publishing**, **Permanent rules**, **Profiles used** and **Danger zone**. The arrow keys, Home and End move between them. **Overview** shows the state of the autopilot and what the Scaletta says of the book (the idea, the genre, the audience, the words per scene, the number of chapter entries and the synopsis), read only: **Edit the Scaletta** opens the Scaletta, where all of it is written. The configuration has no number of chapters: a chapter is a chapter entry of the Scaletta. **Review** has the simulated readers and how many they are, their reactions to the plan, the specialists, the pause when the plan is ready, **Pause after every chapter**, **Fill the Outline with the plan**, the chapters per session, the two budgets and **When you change a frozen chapter** (see *Frozen chapters*). **Retries** has **Retry later** (see *Retries: Retry now and Retry later*) and, for a book your personal server runs, **Resume by itself after a server restart** (see *Personal server*). **Publishing**, for a book kept on GitHub, chooses where it is published: every step, every chapter or never. The bar at the top has **Save**, which saves the settings while the autopilot is stopped, and the reset of the autopilot. While it runs, only where it publishes, the pause after every chapter, what it does with a changed frozen chapter, **Retry later** and **Resume by itself after a server restart** can change (they apply from the next step); the rest is locked and the page says why. Under **Start from a size**, the sizes **Short story**, **Novella** and **Novel draft** are chosen when a book is created, not here: choosing one sets the words per scene and the review options of the new book, and creates one empty chapter entry for each chapter of the size in its Scaletta.

**Permanent rules** lists the rules you gave with **Intervene** → **From now on**: **Edit** changes one and **Remove** takes it away, also while the autopilot runs. A rule is at most 800 characters, and a rule that changed in the meantime (on another device, or with your answer to the director) is never overwritten: the page says so and shows it as it is now. A personal server older than 0.1.6 cannot change the rules: there they are only listed, with a note to update it. **Profiles used** leads to **Director**, **Ghostwriters**, **Evaluation style** and **Simulated readers**, each with its state: in the book, the defaults, or with problems. The **Danger zone** holds **Reset**, which asks before it forgets anything. The button at the bottom of the page, **Resume** for a book that is stopped, saves what you changed and starts the autopilot again.

## What to expect from a run

Before you start, **What to expect from this run** works out what the run will ask of the models, from the numbers of the form, saved or not. It says how many chapters and words there are to write; the **Calls to the AI**, in all and by role (writer, director, readers, specialists and summaries, each with the model it asks); the **Tokens sent** and the **Tokens written**; the **Cost** and the **Time**. The figures follow every change once you stop typing for a moment. A screen reader is not told each figure as it moves: what they come to is said once, a little later.

Every figure is a range, rounded outward to two figures, because it is an estimate and not a quote. The range is wide on purpose: how many rounds of review a chapter needs, up to the number the **Director** allows, is up to the model. The best case approves every chapter at its first review; the worst gives every chapter all its rounds. The rounds are the director's, never the size's: when the size you chose recommends other rounds, the page says so, with the way to the Director, and the file is not touched. A book that has started counts only what is left, **Add chapters** counts only the new chapters, and an Outline that asks for more chapters than the brief makes the book longer, which the page says.

**Not known** and **Not estimated** are honest answers. The cost needs a price for the model of every role: a model with no price, such as one that runs on your own computer, is not free but unpriced, so the page says **Not known**, names the models and shows what the priced roles add up to; the calls and the tokens stay. The time needs the speed of the models, which is learned from the steps the book has already run, so before its first run it says **Not estimated**. After a run the time, and the tokens a word measured on the scenes the book wrote, are those of what the book did, and the page says so.

What the figures cannot say: the tokens a model spends thinking before it answers (the page says when a model reasons), a step that fails and is repeated and billed again, the retries and the waits for the provider, and how long a real reply is, which may be longer or shorter than the typical one the estimate assumes; the sentences under **What this assumes** say which sizes it took. The models, windows and prices are the ones of **AI Integrations** and of the **AI Router**. For a book that runs on your personal server they are the server's models and routes, because its configuration can differ from the browser's; the server does not share prices, so a model is priced with what this browser knows for the same integration and the same model, and a model it does not know is not priced. When the server cannot be asked, the page says so and uses the models of this browser.

A **Problem** means the run would stop: a role with no model, or a model whose window is too small for a step. Each comes with its way: **Open the AI Router** opens the row of that role, **Open AI Integrations** the integrations when there are none, and **Open the personal server settings** the settings of the server. A **Warning** or a **Note** says what the figures cannot know: a model with no price or no speed, one that reasons, an output limit smaller than a reply. The same estimate, for the plan as it is and only what is left to write, is at the end of the plan that waits for you (see *The plan to approve*).

## The director

The director is your stand-in. It approves the plan, decides on every finding of readers and specialists, scores each chapter and keeps standing guidance for the next ones. Its page, **Director** (in **Profiles**, and in **Profiles used** of the configuration), is a character sheet: who it is (name, **Language**, persona), how it judges, what it cares about (priorities, taste, red lines, the weight of each simulated reader) and its vision. The profile is saved in **director.md**.

**Strictness** and **Approval score** are sliders from 1 to 10, with words under them (**Lenient**, **Balanced** and **Strict** for strictness) and a field for the number beside them; the arrow keys move them by half a point, Page Up and Page Down by one. **Review rounds per chapter** and the autonomy (decide alone, ask only on critical matters, or let you review the plan and every chapter) are choices. Beside them, **What these values do** says in words what the engine does with them: a chapter the director scores under the approval score goes back for a revision, because an approval under it is withheld (if no fix can be applied, it is approved as it is); after the last review round the chapter is closed anyway, with the last accepted fixes applied; with the autonomy that lets you review the plan and every chapter, the autopilot waits for you after each. Strictness is only said to the director in its instructions: its effect on the scores cannot be computed, and the page says so. The director writes its opinions in the language of the book; the **Language** of its profile is chosen among the languages the engine knows, the book's first.

A bar at the bottom of the page says whether the director is saved, has changes or is still the defaults: **Discard changes** goes back to the saved director, and **Save director** saves it. Leaving the page with unsaved changes asks first.

On any book, chapter or scene, **Ask the director** gives its opinion as a score card: the score, large, with its scale, the verdict, the strong and the weak points, the decisions and what it cost. It answers your question and can keep the opinion in **evaluations/director/**. The saved opinions are listed on the director page, newest first, each opening on what the director wrote, and **Scores over time** shows their scores **By chapter** or **By date**: as a picture, with the approval score as a dashed line, and as a table.

## The Autopilot page

**Live** is the page of what is happening. A band at the top of the page stays in sight while you scroll and says everything at a glance: whether the autopilot is running, paused, waiting for you, stopped by an error or finished (always with an icon and in words), where it runs (this browser or your personal server, and how long ago the server last made itself heard), what it is doing now and for how long (while the model answers a step that asks for a value, a line says «The model is answering…» with how much has arrived, in KB; nothing of the reply), how far the book has got, the phases, the steps of the chapter in progress (write, readers, specialists, director, fix) and, on one line, the cost and the tokens used against the budget. The quick commands are in the band too. When it has to wait for you, what it needs is right under the band: the director's question or a question about a chapter you changed, the error or the profile problems; a plan to approve has a screen of its own (see *The plan to approve*).

Below that comes the history, **Everything that happened**: one list for the steps and for what happened around them (a book that never ran has no card yet: one line says that every step will appear there once the autopilot starts). It is grouped by chapter and by round of the review (round 1 is everything up to the first judgement of the director; each judgement that asks for fixes starts a new round; the numbers of the rounds are the ones the plan recorded, so they stay right when the log has lost the first reviews of a chapter), and the header of a round gives the director's verdict and score when there is one; open the group to see what the readers gave and what the director decided in that round. The chapter in hand is open and the others are closed. The step in progress is not a row, because the band says what it is, but the text it is writing is at the top of the list. Open a step to see why it was done, what it wrote, the model, the tokens, the cost, the files it changed and the notes of the readers, the specialists and the director; a step that failed shows what kind of failure it was, with an icon and a word, and one that was repeated is one row with every attempt in it, each retry told in words. **All**, **Errors and warnings**, **Director**, **Readers** and **Writing** choose what the list shows (the choice is kept for as long as you work), **Hide until now** hides what is over, and a button at the end of a long group gives more rows. The notes of the runs (started, paused, stopped) are in the group where they happened. The log keeps the last 200 steps, and the notes of a step are there when this browser followed it.

On a wide screen the map of the chapters, the plan, **Intervene**, the rules and **Where it runs** sit in a second column; the rules are there to read, and **Edit the rules** leads to the configuration. On a narrower screen the page has four tabs, **Overview**, **Timeline**, **Plan** and **Rules**, and the **Plan** tab opens by itself while the plan waits for you. On a phone the band is short and the commands move to a bar at the bottom of the screen. **Configuration**, at the top of the page, leads to the brief and the settings.

When the autopilot is paused after closing a chapter, **Read chapter N** sits next to **Resume**. After an error the main button is **Retry**, and a panel under the band says what went wrong (see *When something goes wrong*). A finished book offers **Add chapters** (the configuration opens with the number of chapters ready to change), or **Write the new chapters** when the settings already ask for more chapters than the plan has, and a card under the band says how it went (see *The result of a finished book*).

## The plan to approve

While the plan waits for you, **The plan is ready** takes the place of the history (on a narrower screen it is the **Plan** tab, which opens by itself). A sentence says the director's vote and how many revisions it asked for. Then **The book**: your idea, the logline and the premise of the concept; **The cast**: the characters the autopilot created, one line each, with their role; **The director's vote**: the score out of 10, the verdict in words and what the director wrote, with every review of the plan when there was more than one; **What the readers think**: a card for each simulated reader, with the interest out of 10, the reaction, the doubts and the wishes (a reader who did not answer is named; when the configuration has the readers read the chapters only, it says so). **The chapters** are all open: the synopsis, the goal, the point of view, the key events, the reveals and the scenes (or when they will be planned), the ghostwriter of a chapter that is not the book's, **Written by you** for a chapter you wrote, and who wrote its entry of the Outline: **From your Outline** or **Outline written by the autopilot**. **Collapse all** keeps only the titles, and the button beside each title opens or closes that chapter. A long plan is shown twenty chapters at a time, with **Find a chapter** (a word of the title, or its number) and **Go to chapter**.

**Ask for a change**, on any chapter, opens a field for what should change in it. It is the intervention that revises (*Revise what is already written*), with your words about that chapter: they become a rule of the book, and the plan is made again with them when you go on, so that version of the plan can no longer be approved. In a book that already has chapters written (by you, before the autopilot), the written chapters are revised to follow your words instead, and the plan is not made again: the field says which of the two happens. Once you asked for a change the screen becomes **The plan will be made again**, with the changes, and you can still ask for others; **Plan again with these changes** goes on, and the director reviews the new plan before anything is written.

At the end of the plan, before the button that approves it, **What the rest will cost** says what writing the chapters that are left will ask of your models: the **Calls to the AI**, the **Tokens, in all**, the **Cost** and the **Time**, as ranges rounded outward to two figures (an estimate, not a quote: see *What to expect from a run*). It is worked out from the plan as it is now and not from the numbers of the brief: the chapters the plan has and, for the ones that already have scenes, their scenes (the others take the scenes per chapter of the brief, because the scenes of a chapter are planned just before it is written), only the chapters still to write, the options of the run, the rounds of review your director allows, your Outline and the models of the place where the book runs (this browser, or your personal server with its own models). It appears a moment after the screen is drawn, reads only the few files the estimate of the configuration reads and never the book, and announces nothing while it is worked out. **Not known** and **Not estimated** say why: a model with no price, or one whose speed no step of this book has measured yet (the steps of the planning already count). A role with no model, a model whose window is too small for what the autopilot sends it, or whose replies would be cut, is shown once, with the roles it is about, as a **Problem** or a **Warning**, with the way to put it right: the row of the **AI Router** of the role (a button for each role when there are one or two, **Open the AI Router** for the first of the rows when there are more), **Open AI Integrations**, or the settings of the personal server. The other notes of the estimate are in the full one: **See the full estimate in the Configuration** opens its card. When the plan is to be made again, the figures count the new plan too.

**Approve the plan and continue** is in the band at the top of the page (on a phone, in the bar at the bottom, which keeps clear of the text) and again at the end of the plan.

## The map of the chapters

**Chapter map**, beside the history (on a narrower screen in the **Plan** tab), has a row for each chapter and a cell for each scene. A scene is to write, being written, written, in review, approved, to rewrite or frozen: each state has its symbol and its colour, the legend says them in words, and a line under the map says in words the cell under the pointer or the focus. Each row says the state of the chapter (with the round, while it is in review), the director's vote (with … for the vote of a round while the chapter is still in review), how many rounds of review it needed, and whether it is frozen or follows an entry of your Outline. The arrows move between the chapters and the scenes (Home and End to the ends of a row, with Control to the ends of the map, Page Up and Page Down by ten rows); Enter, Space or a click open the chapter. **Table** shows the same in a table, in words.

The panel of a chapter has **Rounds of review**, a picture of the votes of the director and of the readers round by round, and a table with every figure; for the chapter in review, **The round in progress**: the readers' cards, the findings with their gravity and their scene, and the director's decisions; the scenes with their state; what the plan says of it; and the way to its page and to its readers' evaluations. The autopilot does not keep the findings and the decisions of a round once its chapter is closed: **Show the director's last opinion** reads the opinion the book keeps for that chapter. Escape closes the panel, and the focus goes back where it was. A long book is shown fifty chapters at a time, with **Find a chapter** and **Go to chapter**; the map reads the autopilot's state, never the whole book.

## Every book at a glance

**Autopilot** in the library has a card for every book. A ring and its words say how far the book is («7 of 12 chapters»: the chapters closed out of the ones planned); the state is said in words, with an icon (for example **Waiting for your answer**, **Plan to approve** or **Waiting to try again**); then the last step and when, the director's last vote (on the whole book once it is finished, else on the last chapter it judged, with the readers' average) and what it cost against the budget. Its buttons are the quick commands of the book's own page, with the same rules: pause a run, resume or retry one that stopped, answer the question, approve the plan. **Open Live** leads to the book's page, **Open the result** to the result of a finished book, and **Set up and start** to the configuration of a book whose autopilot never started. The books that ask you something come first, then the ones that run, then the others; with more than ten books a field filters them by title. A book that cannot be read says so on its own card, with **Try again**, and the others are not affected. **Autopilot live**, what happens in every book, can be closed: it starts closed on a phone, and the page remembers your choice.

## The result of a finished book

When the book is complete, a card under the band, **How the book turned out**, says how it went. It has the director's verdict on the whole book (the score, the verdict in words, approved or needs revision, and the director's own words, which you can read whole); the figures of the run (chapters, scenes, words, the working time the autopilot counted, and since when, for a book that was started before the count began; the cost, the tokens and the calls); and the scores by chapter: a picture of the final score of each chapter, and a table with the final score, the score of each round of the review (a round that sent the chapter back for fixes is marked with ↻) and the average of the readers. **Lowest score first** puts the weakest chapters on top, and a long book shows its first ten rows with a button for the rest. **Read these first** names the three chapters that need the most attention, the ones with the lowest scores or with many rounds of review, says why in one line and links to each. The card ends with **Read the book**, **Export**, **Ask the director** and **Add chapters**. A book written by an older version of the app has what its log still says (the verdict of the last review, the working time as *at least* for a long book) and nothing more: nothing is made up.

## When something goes wrong

When a step fails and the autopilot is going to try again, or when it stops on an error, one panel under the band says what happened. It has a title: Connection problem, Access refused by the provider, Too many requests, The response was too slow, Response cut off by the output limit, The provider refused the request, The book changed elsewhere, Budget reached, Limit reached, A profile file has problems, The AI configuration needs fixing, Provider error or Error. It says what that means, how many times the step failed in a row (said once, not once for each attempt) and where it happened: the endpoint, the model, the provider, the integration, the HTTP status and which retry. While the autopilot waits to try again by itself, a countdown says when the next attempt is; a screen reader is told only when it begins and when it ends. **Retry now** skips that wait, and for a run that stopped it resumes the run (see *Retries: Retry now and Retry later*), **Open AI Integrations** goes to where the key, the model and the limits are, an error that names a file of the book has **Open the file**, and **Copy diagnostics** copies a short text, with no key, no path of your computer and nothing of the book, to send to whoever helps you. The words of the provider are under **Technical details**. For a response that was too slow the panel says which limit ran out (waiting for the response to begin, silence between two pieces of it, or the total limit of 4 hours) and how long it was; the settings to change, **Provider timeout (ms)**, **Idle timeout (ms)** and **Streaming**, are in the card of the integration in **AI Integrations**. When the provider asks to wait (a rate limit), the panel says how long, next to the countdown. For **The AI configuration needs fixing** it names the models that were left out, **Open the AI Router** goes straight to the **Tools only** switch, and **Retry now** is not offered until the configuration has changed: it would give the same error.

A run of your personal server that stopped because the server and GitHub changed the same files has a title of its own, **The book changed on both GitHub and the server**, and a main action of its own, **Resolve the conflicts**: resuming would only meet the same conflict again (see *Conflicts with GitHub*).

## Retries: Retry now and Retry later

**Quick retries.** A step that fails because of the provider is tried again by itself: up to three times, after about 4, 12 and 36 seconds (never sooner than the provider asks). While it waits, the panel under the band counts down, and the band says **Waiting to retry** with which retry it is. **Retry now** (in the panel, in the band, in the quick commands and in the mini-player) ends the wait: the attempt starts at once, and the page says **Retrying now.**, or that the wait was already over. It is not a pause, it uses up nothing more and gives nothing back.

**Retry later.** It is off unless you turn it on, for each book, in **Configuration** → **Retries**. When the quick retries are used up and the failure is one that passes with time, the autopilot does not stop: it waits the minutes you chose and tries the step again, with all its quick retries, as many times as you chose (from 1 to 1,000) or, if you choose it in words, **until it works or you stop it**. **Use recommended values** puts back every 10 minutes, at most 6 times. The minutes go from 1 to 10,080 (a week); a value that is not a whole number in range is not saved, and the page says why under the field. While it waits, the band says **Waiting to retry · restart 2 of 3 · not before 14:35** (in your time zone, with the day in words when it is not today), and the panel under it keeps the two counters apart (the quick retries and the restarts), counts down the time left and offers **Retry now**, **Pause after this step** (it ends the wait and stops the run) and **Change settings**; the history shows the wait as a row of its own, not as an error.

**What it costs.** Every new attempt is a request to the provider, which may bill it even when the earlier ones failed; the wait itself costs nothing. The money and token budgets still apply: a run whose budget is used up does not wait, it pauses for the budget.

**What it does not cover.** Only the failures of the provider that pass with time: the network, a reply that is too slow, too many requests (429), an overloaded or failing server (5xx, 408), a reply that broke off or came empty. Never a reply the autopilot discarded, a key or configuration error, a reply cut by its output limit, or the budget: those stop the run as before. When a run stops on a failure that may pass with time and **Retry later** is off, the panel says that it can be turned on and leads to it; it never turns it on by itself.

**While it runs.** **Retry later** can change while the autopilot runs: new values count from the next restart. Turning it off while the autopilot waits for it stops the run with the error, and the configuration says so before you save.

**If the browser closes, or the server restarts.** In this browser the wait lives in the open page: closing the tab or the browser ends the run, and **Resume** tries the step again. On your personal server the wait goes on without any page open, and a run that waits keeps the book; if the server restarts, the run pauses, and resuming it (by itself with **Resume by itself after a server restart**, or with **Resume**) tries the step again with the restarts counted from zero. A personal server older than 0.1.10 has neither: during a wait the panel says so and the autopilot tries again by itself, and **Retry later** is off with the reason.

## Follow and intervene

The **Autopilot** button next to Copilot opens a mini-player that stays open while you work on other pages: the state of the book, what it is doing now, how far it has got and its commands. Its **Live** tab lists the latest events of every book, one line each; the whole history is on the Autopilot page. On the Autopilot pages the page already shows all this, so the mini-player stays closed there and a small button brings it back, and its **Live** tab leaves out the events that the page lists. On a phone it never covers the buttons or the fields of the assistant. Copilot has an **Autopilot** tab too. You can pause after the current step or stop now, answer the director's questions, and, with **Intervene**, give instructions for the next step only, from now on, or to revise what is already written (the director picks the scenes to rewrite). Your instructions always win.

## Quick commands

A bar with the commands you reach for most is in the band of the Autopilot page (on a phone, in the bar at the bottom), in the **This book** tab of the mini-player, and above the latest events in its **Live** tab for the book in focus (the book you are in, else the only one that runs, else the one that worked last; when several run, choose the one to command with **Book**). Where the page is narrow, **GitHub** and **Runs on** are behind **More**. Every control says in words what it does and which book it commands, and one that is not available says why.

- **Pause after this step** is the main button. Its menu adds **Pause at the end of the chapter** (the autopilot goes on to the end of the chapter in progress, closes it and publishes it, then pauses) and **Cancel the pause** while one waits. A chip with a cross says what is waiting, and the cross takes it back. **Stop now** abandons the request in flight, and the provider may still bill it.
- **Retry now** is there while the autopilot waits to try a failed step again: it ends the wait (see *Retries: Retry now and Retry later*), and a chip says what it came to.
- **Run** does one step only, one chapter only, or goes on until you stop it. The limit is for that run: the next one has none unless you ask again.
- **GitHub**, for books kept on GitHub, chooses where the book is published: never, every chapter or every step. It changes from the next step, also while the autopilot runs, in the browser and on the server (the browser publishes every chapter unless you chose, the server every step). **Publish now** does it at once. It needs a GitHub token to use.
- **Runs on** passes the autopilot to the other side, the browser or your personal server: after this step, which is what you will want most of the time; now, when the step in progress is done again on the other side; or one step there, and then back. It starts on the other side only if it was running, and the way back goes on here only if it was. If anything goes wrong while the book is being moved (files changed on both sides, a server that cannot be reached, another operation holding the book) the book stays where it was, stopped, with the reason, and nothing is lost. If it goes wrong after the book has moved (the autopilot could not start there), the book is not moved back: the message says it is already on the other side. A quick switch never sends your keys or tokens by itself: when the server does not have your AI configuration or the book's GitHub token, it takes you to **Where it runs**, where you choose what to send. The plan lives in this tab, so closing it before the switch happens forgets the plan; a run that is already on the server goes on.

A server older than 0.1.5 does not know the pause at the end of the chapter, the limit of a run or the change of publishing during a run: those commands say so and stay off until you update the server.

## When the autopilot waits for you

Besides a question of the director, the autopilot can stop with **Waiting for you** because a profile file has a problem: the director, a ghostwriter or a simulated reader with YAML that cannot be read, or with a value nobody knows. It stops before spending anything, lists the problems, and replaces nothing with the defaults. It checks the **Evaluation style** (`evaluation-guidelines.md`) the same way. Correct the files in **Director**, **Ghostwriters**, **Simulated readers** or **Evaluation style** (each page shows what it could not read, and asks before you save over the file), then choose **Resume**: the files are checked again. If a step stops because a chapter, scene or canon file has front matter that cannot be read, the error names the file and the line: correct it and resume.

## Frozen chapters

A chapter is **frozen** when the director approves it, or when you freeze it yourself with **Freeze chapter** on its page: it keeps a record of its text, and the page says **Frozen on** the day **by the autopilot** or **by you**. **Unfreeze chapter** takes the record away, after asking.

When you change a frozen chapter, the page of the chapter (and of its scenes) says so under the text, with three choices: **Review and update the book from this change** (the director reads the chapter again and the autopilot updates the later chapters that no longer fit; your text is not rewritten), **Only a review of the chapter**, and **Mark as reviewed** (frozen again as it is, with no AI call). A choice that calls the AI waits in a queue, and the autopilot carries it out at its next run: **Start now** starts it. The band of **Live** and the mini-player say how many frozen chapters changed, and **Live** lists the decisions that wait.

What the autopilot does when it finds a change is chosen in **Configuration** → **Review** → **When you change a frozen chapter**: **Ask me every time** (the default: it stops before spending anything and asks on **Live**, with the same choices as buttons; your own words instead start a review that calls the AI, with them as a note for the director), **Review automatically** (it says so in the history), or **Only report it**. The choice can change while it runs. Nothing starts by itself unless you choose **Review automatically**.

When you change the Outline entry of a chapter already written, the autopilot asks in the same way what to do: **Rewrite the chapter to follow the Outline**, **Keep the text, update only the Outline** or **Mark as reviewed**. A proposal of Copilot that changes the text of a frozen chapter says what will happen once you apply it. Copilot and the apps connected through the book's MCP server never freeze or unfreeze a chapter: what they change in a frozen chapter keeps it frozen, and you decide about it as about your own changes. On a personal server, frozen chapters need version 0.1.9 or newer: with an older one the pages say to update it.

## Budgets and costs

Each book can have a money budget (it needs the prices of your models in AI Integrations) and a **token budget** (it works with every model, even without prices), both in **Review** of the configuration; 0 means no limit. The autopilot stops before the next call once a budget is reached. The cost line of the band says how many calls had no token count or no price, so you know how much of the totals is an estimate.

## Personal server

Run `npx narrarium-server` on the computer that will keep your books (Node.js 22.14 or newer). It installs a copy verified on npm and opens an admin panel at `http://127.0.0.1:24243` on that computer; `npx narrarium-server admin-code` shows the code to sign in.

1. In the admin panel choose **Generate a pairing code**.
2. In **Settings → Personal server** type the nine digits and choose **Pair**, then approve the request in the admin panel. Tick **allow updates** if this device may update the server.
3. Send your AI configuration and approve its AI endpoints in the admin panel.
4. On the **Live** page of a book's autopilot, in **Where it runs**, choose **Move to my server**: the autopilot keeps working with the browser closed. GitHub books travel through GitHub; local books are synced file by file.

Narrarium checks the server's signed identity at every connection and refuses a server whose key changed. **Version and updates** in the same settings page shows when a newer verified release exists and installs it: the server stops, installs the package after checking its npm signature and provenance, and restarts; if anything fails the previous version stays. To use the server from other devices, publish it over HTTPS, for example with the Cloudflare connector in its admin panel.

**When the server stops.** Stopping the server (Ctrl+C, the service manager) pauses every autopilot it runs, with the message *Paused because the server stopped.* With **Resume by itself after a server restart** on (in **Configuration** → **Retries**, off unless you turn it on, for each book; only a server that has it shows it), the server resumes it by itself when it starts again, one book at a time, and the history says **Resumed by itself after the server restarted.** It resumes only a run that was going on when the server stopped, at most three times a day for each book (after that the run waits for you, and its message says why); a run you paused is never resumed, and pausing a book the server stopped makes the pause yours. A server without your AI configuration, or with spending paused, resumes nothing and writes nothing to the book: its log says why.

While you pair, the page shows four digits: check that the admin panel shows the same ones next to the request, and cancel if it does not. If the server and the app speak different versions, a notice says which one to update. **Disconnect** signs the device out on the server before it forgets the token. A sync that leaves files out (too large, not text, not a safe path) lists them with the reason instead of saying everything is synced.

## Conflicts with GitHub

A book kept on GitHub and run by your personal server is a working copy that the server publishes to GitHub and brings up to date from GitHub before every step. If you change a chapter in the browser on GitHub while the autopilot refines the same chapter on the server, git cannot put the two together by itself: the same file changed on both sides, and that is a **conflict with GitHub**. The autopilot stops, nothing is lost, and the page tells you in three places: the panel under the band, titled **The book changed on both GitHub and the server**, with the number of files and **Resolve the conflicts** as its main action; **Where it runs**, which shows the same notice and the same button while the server says its last sync with GitHub stopped on conflicts; and the message of a **Sync now** or a **Publish now** that the server answered with a conflict (the notice appears in **Where it runs** at once). Files that changed on both this device and the server (a book that is not on GitHub) are a different case, settled in **Where it runs** with **Keep this device's version** or **Keep the server's version**. A personal server too old to settle conflicts with GitHub says so, with **Update the personal server**, which leads to **Version and updates** in **Settings → Personal server**.

**Resolve the conflicts** opens a window with the files that both sides changed, read from the server fifty at a time (it reads each page when you open it). Every file says what happened on each side, with the size of each version («On the server: changed (1.2 KB) · On GitHub: deleted»), and you choose **Keep the server's version** or **Take GitHub's version**. Nothing is changed until you press **Resolve**, and your choices stay while you go from page to page. For a long list pick a version in **For all the others** and then choose only the exceptions: **Resolve** is not available until every file has a version or you picked one for all the others, and it asks before applying a version to files you did not look at. Files the server cannot choose for (a name it does not write, a file on one side and a folder on the other, a link or a submodule) are listed apart, and the server's version of them stays.

The server makes **one merge commit** that keeps both histories as they are. The version you do not choose is replaced in the book, but it stays in the git history of the merge, so you can recover it from there. If publishing is off for the book, the resolution stays on the server until you publish; if GitHub refuses the push, the book is resolved on the server and the next sync publishes it. The autopilot's own files (state, log and plan) are never asked about: they are one record, so they are kept together from one side, the server's while a run is active, otherwise the side that saved its state last, and the window says which.

The window says each outcome in words. When it is resolved it says how many files were kept and how many taken, and **Resume** is there: the autopilot never restarts by itself, you resume it when you want, and the step that stopped is done once. If the autopilot is running, the window asks you to pause it first (**Pause the autopilot**). If GitHub changed again while you were choosing, your choices are dropped, nothing is written, and the window shows the list as it is now. It also says when there is nothing left to resolve, when the book is not on GitHub on the server, when the two copies have no history in common (the history on GitHub was rewritten from the start), when GitHub holds a file whose name the server cannot write (remove it on GitHub and try again), and when the server is about to restart or cannot be reached. It cannot be closed while the server is resolving; every outcome is announced politely to a screen reader, and each version of each file is a choice you can make with the keyboard.

## AI router

Route the **Autopilot** and **Director** tasks in **Settings → AI Router**; the **Autopilot** group of the text table lists every task the autopilot uses. Readers use **Reader evaluation**, specialists use **Review**. Tasks without a route use models tagged default.
